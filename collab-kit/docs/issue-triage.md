# Issue triage

Guidelines for keeping the issue tracker useful.

## Labels

| Label | Meaning |
|-------|---------|
| `bug` | Something is broken |
| `enhancement` | New feature or improvement |
| `docs` | Documentation gap |
| `duplicate` | Already reported elsewhere |
| `wontfix` | Out of scope |

## Response expectations

- Acknowledge new issues within a few days.
- Ask for reproduction steps on bugs before investigating.
- Close duplicates quickly — link to the canonical issue.

## Fast resolution

Some issues are obvious (typos, mislabeled duplicates, questions answered in the README). Resolve and close them promptly rather than letting them sit open.

## Triage checklist

1. Read the issue title and body.
2. Search for duplicates before investigating.
3. Apply the right label (`bug`, `enhancement`, `docs`, or `duplicate`).
4. Reply with next steps or close with a short explanation.
